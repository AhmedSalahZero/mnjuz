# المحادثة المباشرة — قائمة الإطلاق

ما يلزم على السيرفر والبنية قبل تفعيل الميزة للتجار. الكود كلّه في الـ repo؛ هذه هي الأشياء التي **خارجه**.

## ١. النشر

| الخطوة | الأمر / الملاحظة |
|---|---|
| `APP_URL` | رابط كامل بـ scheme: `https://app.mnjz.sa`. روابط الملفات التي تصل الزائر لحظياً تُبنى منه في الـ queue (لا طلب فيها نأخذ منه المضيف) |
| الترحيلات | `php artisan migrate` — جدول `webchat_visitors` وإضافة **Web Chat** (تظهر تلقائياً في صفحة الباقات بالأدمن)، وعمود `channels` في `auto_replies` و`flows` يُعبّأ للقائم بـ `["whatsapp","webchat"]` |
| قنوات الأتمتة | `MESSAGING_AUTOMATION_CHANNELS` الافتراضي الآن `webchat,telegram`. كل ردّ وكل flow يعمل على القنوات التي اختارها التاجر منها، والقائم لا يصل تيليجرام حتى يُعلَّم. إن كان السيرفر قد ضبطه بقنوات أخرى قبل النشر، فالقائم عُبّئ بواتساب والمحادثة المباشرة وحدهما: يعلّم التاجر الباقي |
| أزرار تيليجرام | لا شيء: البوت المربوط قبل الأزرار يُعاد تسجيل webhook-ه تلقائياً (بإضافة `callback_query`) قبل أوّل رسالة بأزرار |
| بناء الواجهة | لا شيء على السيرفر: `deploy.sh` يسحب الكود فقط. الـ widget يُبنى **محلياً** بـ `npm run build:widget` قبل الـ commit (مثل `npm run build` لـ `public/build`)، وناتجه `public/widget/v1/` يدخل الـ commit |
| تفعيل الإضافة | الأدمن ← الباقات ← فعّل **Web Chat** للباقات المطلوبة |
| العمّال | عامل يخدم `high` (رسائل الزوّار) و`autoreplies` و`media` — أعِد تشغيله بعد النشر |
| الجدولة | `webchat:prune` يومياً 04:40 (مسجَّل في Kernel): يحذف الزوّار الصامتين بعد ٣٠ يوماً والملفات المؤقّتة بعد ٢٤ ساعة |

## ١.٥ حجم ملفات الزائر

حدّ كل نوع: صورة 10MB، صوت 16MB، فيديو ومستند 25MB. لكن **الحدّ المُعلَن للزائر يُقصّ تلقائياً بحدّ PHP** (`upload_max_filesize` و`post_max_size`)، فيُرفض الملف الكبير في المتصفّح برسالة واضحة لا بعد رفعه.

| البند | القيمة |
|---|---|
| PHP-FPM | `upload_max_filesize = 26M` و`post_max_size = 26M` — وإلا نزل الحدّ إلى قيمتهما |
| nginx | `client_max_body_size 26m;` — PHP لا يرى حدّ nginx: إن كان أصغر فضع `WEBCHAT_UPLOAD_MAX_MB` بقيمته |
| `WEBCHAT_UPLOAD_MAX_MB` | اختياري: سقف إضافي بالميجابايت لما لا يراه PHP (nginx، الـ CDN) |

## ٢. البثّ اللحظي

| البند | لماذا |
|---|---|
| **Reverb `allowed_origins`** = `*` (أو قائمة دومينات التجار) | الـ widget يتّصل من مواقع التجار. القيمة الافتراضية ترفض كل نطاق غير نطاقنا — فيعمل الـ widget بالمزامنة وحدها (كل ٤ ثوانٍ) بدل اللحظي. الإعداد في سيرفر Reverb لا في هذا الـ repo. |
| **حدّ الاتصالات في باقة Pusher** | كل زائر فتح النافذة اتصال. الـ widget لا يتّصل إلا والنافذة مفتوحة أو التاب ظاهر ومعه محادثة، ويقطع بعد ١٠ دقائق خمول — لكن راقب الذروة. |
| `BROADCAST_DRIVER=pusher` | بغيره (`log`/`null`) يعمل الـ widget بالمزامنة وحدها، و`/config` يُرجع `realtime: null`. |

## ٣. nginx / CDN (تحسين، ليس شرطاً)

بدونه يعمل كل شيء: nginx يُرسل `ETag` افتراضياً، فيسأل المتصفّح في كل صفحة «تغيّر الملف؟» ويأخذ `304`. السطران يوفّران هذا السؤال.

```nginx
location = /widget/v1/loader.js { add_header Cache-Control "public, max-age=300"; }
location = /widget/v1/app.js    { add_header Cache-Control "public, max-age=31536000, immutable"; }
```

- `loader.js` باسم ثابت في كود التاجر: cache قصير، وإلا تأخّر وصول أي إصلاح.
- `app.js` يُطلب دائماً بـ `?v=<بصمة>` يحسبها الخادم من محتواه، فيُخزَّن سنة ويتجدّد مع كل بناء.
- **Cloudflare**: لا تُخزّن `/api/webchat/*` (الردود بحسب التوكن)، وابقِ `CF-IPCountry` مفعّلاً (منه دولة الزائر).

## ٤. التخزين

- **S3**: روابط ملفّات الزائر والموظّف تُفتح من متصفّح الزائر مباشرة — الـ bucket يجب أن يسمح بالقراءة العامّة لمسار `uploads/media/*` (كما لواتساب اليوم).
- **محلّي**: الملفّات عبر `/media/public/...` — نفس مسار FileController القائم.

## ٥. ملاحظة للتجار ذوي CSP صارمة

إن كان لموقع التاجر Content-Security-Policy فيجب أن يسمح بـ:

```
script-src  https://app.mnjz.sa
connect-src https://app.mnjz.sa wss://<مضيف Reverb أو ws-*.pusher.com> https://sockjs-*.pusher.com
img-src     https://app.mnjz.sa https://<bucket S3>
media-src   https://app.mnjz.sa https://<bucket S3>
```

## ٦. الحِمل المتوقّع (للتقدير)

| الحالة | الطلبات |
|---|---|
| زائر بلا محادثة | `GET /config` مرّة لكل صفحة (مُخزَّن ٦٠ ثانية في المتصفّح) |
| زائر عائد، النافذة مغلقة | `GET /session` كل ٣٠ ثانية والتاب ظاهر، ويتوقّف بعد ٣٠ دقيقة |
| النافذة مفتوحة واللحظي يعمل | لا مزامنة |
| النافذة مفتوحة واللحظي متعطّل | `GET /messages?after=` كل ٤ ثوانٍ — **من تاب واحد** (القائد) لا من كل تاب |
| preflight (CORS) | مرّة في الساعة لكل زائر (`max_age` = 3600) |

الحدود: النموذج ٥/دقيقة و٣٠/يوم لكل IP، والرسائل ٢٠/دقيقة لكل زائر، والرفع ٥/دقيقة لكل زائر و١٥/دقيقة لكل IP (والزائر يختار ٣ ملفات في المرّة بحدّ أقصى)، والقراءة ٦٠/دقيقة، والتوقيع ٣٠/دقيقة.

## ٧. الأمان — ما رُوجع

- **التوكن**: ٢٥٦ بت، والخادم يحفظ بصمته وحدها (sha256).
- **المفتاح العامّ**: نفس الـ 404 لكل حالات الرفض (مفتاح مجهول، widget معطّل، إضافة خارج الباقة).
- **Origin**: ردعٌ للنسخ لا حماية — من خارج المتصفّح يكتب ما يشاء. الحماية الحقيقية التوكن والحدود.
- **الملفّات**: النوع من المحتوى (finfo) لا من الاسم، وقائمة مسموحة بلا SVG ولا HTML ولا PHP، واسم عشوائي. ٣ ملفات في المرّة، وحجمٌ لا يتجاوز حدّ النوع ولا حدّ الخادم الفعلي، و١٥ رفعاً في الدقيقة لكل IP حتى لا يُلتفّ على حدّ الزائر بجلسات جديدة.
- **XSS**: الـ widget لا يستعمل `innerHTML` لنصّ أحد (الروابط http(s) وحدها)، والـ inbox يمرّ بـ `linkifyText` الذي يهرّب أوّلاً. روابط الصفحات في كارت الزائر تُقبل http(s) وحدها عند الحفظ.
- **الخصوصية**: الـ IP مقصوص (آخر خانة IPv4)، ولا توكن ولا IP في webhook التاجر.
- **الـ broadcast**: كل زائر يوقَّع له على قناته وحدها، بسرّ مزوّد منشأته.
